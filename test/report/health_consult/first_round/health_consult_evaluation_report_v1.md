### 3.3 降级策略实现

#### 3.3.1 降级策略设计问题分析

**设计文档描述**（第206-207行）：

- Milvus向量库不可用 → 仅使用Neo4j精确匹配结果
- Neo4j数据库不可用 → 仅使用向量检索结果

**问题分析**：

根据设计文档第47行和第113行的描述，检索策略是**顺序检索模式**：

> 向量检索锚定实体 → 图查询结构化推理增强

这意味着：

1. **Milvus的作用**：锚定用户问题中涉及的Neo4j实体、属性和关系
2. **Neo4j的作用**：基于锚定的实体进行结构化推理增强

**矛盾点**：

- 如果Milvus不可用，Neo4j无法知道要查询哪些实体（因为没有锚定信息）
- 设计文档说"Milvus不可用→仅使用Neo4j结果"，但此时Neo4j没有查询目标

**代码实现分析**（knowledge\_retrieval\_chain.py第295-308行）：

```python
if not anchored_entities:
    # 当没有锚定实体时，fallback到直接用查询文本搜索
    diseases = self._resource.neo4j_handler.search_diseases_by_symptom(query)
```

代码实现中，当Milvus不可用或未返回锚定实体时，会fallback到`search_diseases_by_symptom(query)`，直接用原始查询文本在Neo4j中进行模糊匹配。

**结论**：

- **设计文档的降级策略描述不准确**：不是"仅使用Neo4j精确匹配结果"，而是"使用Neo4j模糊匹配替代精确锚定"
- **代码实现与设计文档不一致**：代码实现了fallback逻辑，但与设计文档描述不符
- **需要澄清**：设计文档需要明确降级策略的具体实现方式

#### N2详细分析：资源池连接管理问题

**问题定位**：

代码位置：[resource\_pool.py:115-116](file:///home/project/MedicalQA/src/resource_manager/resource_pool.py#L115-L116)

```python
def release(self, handle: ResourceHandle) -> None:
    with self._lock:
        resource_id = handle.resource_id
        if resource_id in self._active_resources:
            resource = self._active_resources.pop(resource_id)
            resource.deactivate()  # 这里调用deactivate断开连接
            self._idle_resources[resource_id] = resource
```

代码位置：[neo4j\_connection\_resource.py:70-77](file:///home/project/MedicalQA/src/resource_manager/neo4j_connection/neo4j_connection_resource.py#L70-L77)

```python
def deactivate(self) -> None:
    if not self._is_active:
        return
    if self._adapter is not None:
        self._adapter.disconnect()  # 断开连接
    self._is_active = False
```

**问题影响**：

- 每次资源释放回池时都会断开连接
- 下次使用时需要重新建立连接，增加延迟
- 对于高频访问场景，连接开销较大

**修复建议**：

- 方案A（推荐）：在`deactivate()`中不断开连接，仅在`destroy()`时断开，保持连接池语义
- 方案B：添加连接保活机制，定期检查空闲资源连接状态

**最终采用方案**：方案A，详见任务组D中D2子任务

| 健康风险因子分类模型（NER） | iic/nlp\_raner\_named-entity-recognition\_chinese-base-cmeee | 与健康风险预测模型合计9G | 中文医学命名实体识别 |

**分析结论**：

1. **当前实现合理**：Milvus已完成实体锚定，Neo4j查询是简单的模板匹配
2. **不需要额外小模型**：
   - 显存已接近满负荷（21G总预算，预留2G安全冗余）
   - 当前模型选型已覆盖意图识别和实体抽取
   - Neo4j查询构造不需要复杂NLP能力
3. **未来优化方向**（可选）：
   - 如需更复杂查询推理（如多跳关系查询），可考虑使用LLM生成Cypher
   - 但会增加显存压力和延迟

```python
# neo4j_connection_resource.py / milvus_connection_resource.py

def deactivate(self) -> None:
    """
    停用资源（释放回池，保持连接）
    
    语义：资源从活跃状态变为空闲状态，归还到资源池
    行为：仅标记状态，不断开连接
    """
    if not self._is_active:
        return
    self._is_active = False
    logger.debug(f"[Resource] deactivate: 保持连接，标记为空闲")

def destroy(self) -> None:
    """
    销毁资源（彻底释放）
    
    语义：资源彻底销毁，从资源池移除
    行为：断开连接，释放所有资源
    """
    if self._adapter is not None:
        self._adapter.disconnect()  # 这里才断开连接
        self._adapter = None
    logger.info(f"[Resource] destroy: 断开连接，释放资源")
```
