# 老人健康监测系统-健康咨询子项目 架构设计文档

## 一、架构总览
本项目在原有智能咨询Agent系统五层架构基础上，新增LangChain适配层和Neo4j医疗知识工具模块，形成适配老人健康场景的专用架构。架构保持高内聚低耦合的设计原则，完全兼容原有架构的所有能力。

### 1.1 扩展后的分层架构
```
┌──────────────────────────────────────────────────────────┐
│ 接入层 (controller、service)                              │
│  - 健康咨询接口、健康报告生成接口                          │
│  - 流式响应处理、请求参数校验                              │
├──────────────────────────────────────────────────────────┤
│ 编排核心层 (orchestration)                                │
│  - 健康咨询业务链、健康报告生成业务链                      │
│  - 老人健康场景专用Agent策略、流式执行控制                  │
│  - 上下文管理、状态机管控                                  │
├──────────────────────────────────────────────────────────┤
│ MCP代理层 (mcp)                                           │
│  - LangChain工具代理、Neo4j医疗知识工具代理                │
│  - 工具调用路由、协议转换、性能优化                        │
├──────────────────────────────────────────────────────────┤
│ 工具实现层 (tools)                                        │
│  - Neo4j医疗知识检索工具、健康报告生成工具                  │
│  - 医学知识校验工具、流式内容生成工具                      │
├──────────────────────────────────────────────────────────┤
│ 资源管理与适配层                                          │
│  - Neo4jAdapter、LangChain资源管理                        │
│  - LLM客户端管理、全局资源池化、生命周期管理                │
│  - 外部中间件适配、连接池管理                              │
└──────────────────────────────────────────────────────────┘
```

### 1.2 各层详细职责与交互关系
#### 1.2.1 接入层
**职责：**
- 对外提供HTTP接口，接收总项目后端的请求
- 处理SSE流式响应，实现内容的逐块返回
- 请求参数合法性校验、异常统一处理
- 协议转换，将外部请求转换为内部上下文格式

**上下游交互：**
- 上游：对接总项目后端服务，接收健康咨询和报告生成请求
- 下游：调用编排核心层的业务链入口，传递请求上下文
- 响应：将业务链返回的流式结果直接返回给上游调用方

#### 1.2.2 编排核心层
**职责：**
- 执行业务流程编排，管控健康咨询和报告生成的全流程
- 实现Agent执行策略，驱动工具调用和内容生成
- 管理执行状态，控制流式生成节奏，协调内容生成和返回的步调

**说明：** 对话上下文由总项目后端统一管理，本层仅使用传入的上下文内容，不做持久化存储

**上下游交互：**
- 上游：接收接入层传递的请求上下文（包含总项目提供的完整对话记录）
- 下游：通过MCP代理层调用各种工具能力
- 回调：将生成的内容块实时回调给接入层进行流式返回

#### 1.2.3 MCP代理层
**职责：**
- 提供统一的工具调用接口，屏蔽底层工具实现差异
- 支持标准MCP协议和高效直连两种调用方式
- 工具实例的生命周期管理、缓存和复用
- 工具调用的监控、埋点和限流

**上下游交互：**
- 上游：接收编排核心层的工具调用请求
- 下游：路由到工具实现层的对应工具执行具体逻辑
- 返回：将工具执行结果返回给编排核心层

#### 1.2.4 工具实现层
**职责：**
- 具体业务能力的实现，包括知识检索、内容生成等
- 调用资源管理与适配层提供的LangChain封装接口实现LLM交互和链执行
- 实现Neo4j医疗知识的查询、检索和推理逻辑
- 提供医学知识校验能力，确保内容专业性

**上下游交互：**
- 上游：接收MCP代理层转发的调用请求
- 下游：通过资源管理与适配层获取外部资源连接和LangChain能力接口
- 返回：将工具执行结果返回给MCP代理层

#### 1.2.5 资源管理与适配层
**职责：**
- 全局资源的统一生命周期管理和池化复用
- 外部中间件（Neo4j、LLM服务等）的适配对接
- 封装LangChain框架能力，向上层提供统一的LangChain调用接口
- 资源连接的创建、复用、销毁和监控
- 资源配置的统一管理和热更新

**上下游交互：**
- 上游：为全链路所有模块提供资源访问能力和LangChain封装接口
- 下游：对接外部基础设施（数据库、模型服务等）和LangChain框架
- 回调：资源状态变更时通知相关使用模块

## 二、核心扩展模块设计
### 2.1 LangChain适配层设计
#### 2.1.1 定位与职责
LangChain适配层作为LangChain框架与本系统架构的桥接层，封装LangChain的核心能力，使其符合本系统的接口规范和资源管理要求。

#### 2.1.2 核心组件
| 类名 | 类型 | 核心职责 |
|------|------|----------|
| LangChainAdapter | 适配类 | 封装LangChain框架的初始化、配置、调用逻辑 |
| LangChainTool | 工具实现类 | 实现Tool接口，提供LangChain能力的统一调用入口 |
| LangChainResource | 资源类 | 实现Resource接口，管理LangChain实例的生命周期 |
| LangChainResourceConfig | 配置类 | LangChain相关配置（模型参数、工具配置等） |
| LangChainFactory | 工厂类 | 负责LangChain资源实例的创建与销毁 |

#### 2.1.3 适配逻辑
1. LangChain的所有组件通过GlobalResourceManager统一管理生命周期
2. LangChain的工具调用通过MCP代理层向上暴露，符合系统统一工具调用规范
3. LangChain的Chain、Agent等能力封装为系统可编排的业务单元

### 2.2 Neo4j医疗知识工具设计
#### 2.2.1 定位与职责
Neo4j医疗知识工具是系统的核心知识源，封装Neo4j医疗知识图谱的查询、检索、推理能力，为健康咨询和报告生成提供专业医学知识支撑。

#### 2.2.2 核心组件
| 类名 | 类型 | 核心职责 |
|------|------|----------|
| Neo4jMedicalTool | 工具实现类 | 实现Tool接口，提供医疗知识检索的统一入口 |
| MedicalQueryParser | 解析类 | 将自然语言问题转换为Cypher查询语句 |
| MedicalKnowledgeRetriever | 检索类 | 执行Cypher查询，返回结构化知识结果 |
| MedicalKnowledgeValidator | 校验类 | 对检索到的医学知识进行准确性校验 |
| Neo4jMedicalAdapter | 适配类 | 继承原有Neo4jAdapter，扩展医疗知识图谱专用操作 |

#### 2.2.3 核心能力
- 症状查询：根据症状关联可能的疾病、诊疗建议
- 疾病知识查询：查询疾病的病因、症状、治疗方案、预防措施
- 药物知识查询：查询药物的适应症、用法用量、禁忌、不良反应
- 健康建议生成：根据用户健康情况生成个性化健康指导
- 知识推理：基于知识图谱关系进行医学逻辑推理

### 2.3 健康场景专用业务链设计
#### 2.3.1 健康咨询业务链
```
用户请求 → 问题解析 → 意图识别 → 医学知识检索（Neo4j） → 
LangChain内容生成 → 医学知识校验 → 结果封装 → 返回用户
```

#### 2.3.2 健康报告生成业务链
```
用户健康数据 → 数据清洗 → 维度分析 → 相关医学知识检索（Neo4j） →
健康风险评估 → LangChain报告生成 → 医学内容校验 → 报告格式化 → 返回用户
```

## 四、架构优势
1. **完全兼容原有架构**：扩展部分完全遵循原有架构的设计规范，不破坏原有系统的稳定性
2. **专业知识隔离**：医学知识的查询、校验逻辑独立封装，确保医学内容的专业性和准确性
3. **LangChain能力复用**：通过适配层充分利用LangChain生态的丰富工具和能力
4. **可扩展性强**：支持新增医学知识类型、新增报告模板、对接不同大模型
5. **资源统一管理**：所有资源（Neo4j连接、LangChain实例、LLM连接）均通过全局资源管理器统一管理，保证系统稳定性

### 5.3 模型架构设计说明
#### 5.3.1 部署架构
所有模型统一部署在**资源管理与适配层**的模型服务模块，由全局资源管理器统一管理生命周期、池化复用、监控运维。

#### 5.3.2 调用链路
统一调用路径：编排核心层 → MCP代理层 → 工具实现层 → 资源适配层 → 模型服务模块 → 对应模型
- 模型服务模块对外提供统一的调用接口，屏蔽底层模型实现差异
- 所有模型调用支持异步、批量、超时控制、降级策略

#### 5.3.3 降级策略
模型调用失败时自动切换为基于规则的降级方案：
- 健康风险预测模型降级：使用预设的指标阈值规则计算风险
- 风险因子提取模型降级：使用正则匹配+关键词识别方式提取风险
- LLM降级：返回预设的标准化回答/报告模板，提示用户稍后重试

#### 5.3.4 版本管理
- 所有模型版本固定，代码库中明确记录模型版本号、下载地址、校验和
- 支持模型热更新，无需重启服务即可升级模型版本
- 保留历史版本回滚能力，确保新版本出现问题时快速恢复
