### 3.6 混合检索设计

#### 3.6.1 三集合检索策略

系统采用三集合并行检索策略，从不同维度匹配用户查询：

**检索集合**：

1. **medical_entity**：实体名称检索
   - 检索目标：实体名称与查询的语义相似度
   - 适用场景：实体识别、实体链接
   - 返回结果：实体名称、实体类型、Neo4j节点ID
2. **entity_attributes**：实体属性检索
   - 检索目标：实体属性内容与查询的语义相似度
   - 适用场景：基于症状、病因、预防措施等属性的检索
   - 返回结果：实体名称、属性名、属性值、Neo4j节点ID
   - **重要说明**：entity_attributes集合的数据也包含neo4j_node_id，可以用来锚定实体，用于Neo4j查询
3. **entity_relations**：实体关系检索
   - 检索目标：实体关系描述与查询的语义相似度
   - 适用场景：基于关系语义的检索（如"高血压会引起什么症状"）
   - 返回结果：源实体、目标实体、关系类型、Neo4j关系ID

#### 3.6.2 结果融合算法

**加权融合策略**：
采用加权融合算法综合三个集合的检索结果，权重分配如下：

| 检索集合               | 权重   | 说明                |
| ------------------ | ---- | ----------------- |
| medical_entity    | 0.40 | 实体名称匹配权重最高，优先级最高  |
| entity_attributes | 0.30 | 属性匹配权重次之，提供详细语义信息 |
| entity_relations  | 0.30 | 关系匹配权重较低，补充关联信息   |

**融合算法流程**：

1. **并行检索**：同时对三个集合进行Top-K检索（K=20）
2. **结果去重**：基于Neo4j节点ID/关系ID去除重复结果
3. **分数归一化**：将各集合的相似度分数归一化到[0,1]区间
4. **加权融合**：按权重计算综合得分
5. **结果排序**：按综合得分降序排列
6. **阈值过滤**：过滤综合得分低于0.6的结果

#### 3.6.3 Neo4j节点查询策略

**基于neo4j_node_id的精确查询**：

向量检索返回的结果中包含neo4j_node_id字段，该字段是Neo4j节点的内部ID。系统使用该ID直接查询Neo4j节点，避免实体名称不匹配的问题。

**查询流程**：

1. **向量检索**：从Milvus检索相关实体，获取neo4j_node_id
2. **节点类型判断**：根据entity_type字段判断节点类型（Disease/Symptom等）
3. **精确查询**：使用Cypher语句通过elementId查询节点
   ```cypher
   MATCH (d:Disease) WHERE elementId(d) = $node_id RETURN d.name, d.desc, ...
   ```
4. **关系查询**：查询节点的相关关系（症状、药物、食物等）

**优势**：

- 避免实体名称不匹配的问题
- 提高查询准确性和效率
- 支持多种实体类型（Disease、Symptom等）

**注意事项**：

- neo4j_node_id存储为Neo4j elementId字符串（格式如"4:UUID:序号"），查询时直接传递给Cypher WHERE elementId(n) = $node_id
- entity_attributes集合的数据也可以用来锚定实体，通过neo4j_node_id查询Neo4j节点
