# 老人健康监测系统 数据库说明文档

## 1. 数据库概述

本项目使用两类数据库配合完成医疗知识检索和向量语义匹配功能：

- **图数据库**：Neo4j，存储结构化医疗知识图谱
- **向量数据库**：Milvus，存储医学实体向量，支持语义检索

### 1.1 数据库基本信息

#### 1.1.1 Neo4j 图数据库

- **数据库名称**: DiseaseKG 医疗知识图谱
- **数据库类型**: Neo4j 图数据库
- **部署方式**: Neo4j Aura 云数据库（免费额度）
- **连接地址**: neo4j+s://627658bb.databases.neo4j.io
- **用户名**: 627658bb
- **数据库名**: neo4j (默认数据库)
- **数据规模**：44,657个节点，312,226条关系

#### 1.1.2 Milvus 向量数据库

- **数据库名称**: MedicalEntityVector 医学实体向量库
- **数据库类型**: Milvus 向量数据库
- **部署方案**: Zilliz Cloud 免费云服务
- **备选部署方案**：Docker单机本地部署
- **连接地址**：Zilliz Cloud控制台获取
- **向量规模**：约45万条向量，1024维
- **文档版本**: v1.1
- **最后更新**: 2026-04-10

## 3. Milvus 向量数据库设计

### 3.1 向量数据库概述

Milvus向量数据库用于存储医学实体的向量表示，支持基于语义的相似性检索，为实体抽取、知识检索等功能提供高性能向量查询能力。

### 3.2 向量库结构设计

#### 3.2.1 集合 (Collection) 设计

| 集合名称               | 向量维度 | 索引类型      | 相似度度量  | 实体数量   | 用途            |
| ------------------ | ---- | --------- | ------ | ------ | ------------- |
| medical_entity    | 1024 | IVF_FLAT | COSINE | 44,657 | 存储所有医学实体的向量表示 |
| entity_attributes | 1024 | IVF_FLAT | COSINE | 约6万条    | 存储实体属性的向量表示   |
| entity_relations  | 1024 | IVF_FLAT | COSINE | 312,226 | 存储实体关系的向量表示   |

#### 3.2.2 集合字段设计

| 字段名             | 数据类型              | 说明                                              |
| --------------- | ----------------- | ----------------------------------------------- |
| id              | Int64             | 主键，与Neo4j节点ID一一对应                               |
| vector          | FloatVector(1024) | 实体语义向量，由BAAI/bge-large-zh-v1.5模型生成              |
| entity_name    | VarChar(255)      | 实体名称                                            |
| entity_type    | VarChar(50)       | 实体类型：Disease/Drug/Symptom/Food/Check/Department/Producer/Cure |
| neo4j_node_id | VarChar(50)       | 对应Neo4j节点的唯一标识                                  |

**索引配置**：

- **索引类型**: IVF_FLAT
- **nlist**: 1024 (聚类中心数量)
- **相似度度量**: COSINE
- **检索参数**: nprobe=16 (查询时访问的聚类中心数量)

#### 3.2.3 entity_attributes集合字段设计

| 字段名              | 数据类型              | 说明                                              |
| ---------------- | ----------------- | ----------------------------------------------- |
| id               | Int64             | 主键，自增ID                                         |

### 3.3 向量数据构建流程

#### 3.3.1 数据准备

1. 从Neo4j数据库导出所有医学实体（Disease、Drug、Symptom、Food、Check、Department、Producer、Cure共8种类型）
2. 提取实体名称和对应的Neo4j节点ID
3. 提取实体属性信息（如疾病的描述、病因、预防措施等）
4. 提取所有实体关系信息（共11种关系类型）

#### 3.3.2 实体名称向量化流程

**向量模型配置**：

- **模型名称**：BAAI/bge-large-zh-v1.5
- **向量维度**：1024维
- **最大输入长度**：512 tokens
- **模型存储**：/home/project/MedicalQA/base_models/
- **设备支持**：CPU/GPU自适应

**向量生成流程**：

1. **实体名称预处理**：
   - 医学术语标准化（如"高血压病"→"高血压"）
   - 实体名称清洗（去除特殊字符、统一标点）
   - 实体类型前缀增强
2. **批量向量编码**：
   - 按实体类型分组处理，提高缓存命中率
   - 动态批次大小调整（初始256，根据内存调整）
   - 向量归一化处理，确保余弦相似度计算准确性
3. **向量质量验证**：
   - 验证向量维度正确（1024维）
   - 验证向量值范围正常（无NaN/Inf）
   - 验证归一化误差（<1e-6）

**实体类型前缀增强规则**：

| ------- | ------- | ---- |

#### 3.3.3 实体属性向量化流程

```python
    search_params = {"metric_type": "COSINE", "params": {"nprobe": 16}}
    results = collection.search(
        data=[vector],
        anns_field="vector",
        param=search_params,
        limit=top_k,
        output_fields=["entity_name", "entity_type", "neo4j_node_id"]
    )
    
    entities = []
    for hit in results[0]:
        entities.append({
            "name": hit.entity.get("entity_name"),
            "type": hit.entity.get("entity_type"),
            "neo4j_id": hit.entity.get("neo4j_node_id"),
            "similarity": hit.score
        })
    return entities
```

#### 3.4.2 检索结果说明

- `similarity` 范围: 0~1，值越高表示相似度越高

#### 3.4.3 混合检索API示例

```python
from pymilvus import connections, Collection
from concurrent.futures import ThreadPoolExecutor
import numpy as np

class HybridSearchEngine:
    def __init__(self, uri, token):
        connections.connect(alias="default", uri=uri, token=token)
        self.entity_collection = Collection("medical_entity")
        self.attr_collection = Collection("entity_attributes")
        self.relation_collection = Collection("entity_relations")
        
        self.entity_collection.load()
        self.attr_collection.load()
        self.relation_collection.load()
    
    def search_single_collection(self, collection, vector, top_k=20):
        search_params = {"metric_type": "COSINE", "params": {"nprobe": 16}}
        results = collection.search(
            data=[vector],
            anns_field="vector",
            param=search_params,
            limit=top_k,
            output_fields=["*"]
        )
        return results[0]
    
    def hybrid_search(self, query_vector, top_k=20):
        with ThreadPoolExecutor(max_workers=3) as executor:
            entity_future = executor.submit(
                self.search_single_collection, 
                self.entity_collection, 
                query_vector, 
                top_k
            )
            attr_future = executor.submit(
                self.search_single_collection, 
                self.attr_collection, 
                query_vector, 
                top_k
            )
            relation_future = executor.submit(
                self.search_single_collection, 
                self.relation_collection, 
                query_vector, 
                top_k
            )
            
            entity_results = entity_future.result()
            attr_results = attr_future.result()
            relation_results = relation_future.result()
        
        fused_results = self.fuse_results(
            entity_results, 
            attr_results, 
            relation_results
        )
        
        return fused_results[:top_k]
    
    def fuse_results(self, entity_results, attr_results, relation_results):
        entity_weight = 0.40
        attr_weight = 0.35
        relation_weight = 0.25
        
        fused_dict = {}
        
        for hit in entity_results:
            neo4j_id = hit.entity.get("neo4j_node_id")
            score = hit.score * entity_weight
            if neo4j_id not in fused_dict:
                fused_dict[neo4j_id] = {
                    "entity_name": hit.entity.get("entity_name"),
                    "entity_type": hit.entity.get("entity_type"),
                    "neo4j_id": neo4j_id,
                    "score": 0.0
                }
            fused_dict[neo4j_id]["score"] += score
        
        for hit in attr_results:
            neo4j_id = hit.entity.get("neo4j_node_id")
            score = hit.score * attr_weight
            if neo4j_id not in fused_dict:
                fused_dict[neo4j_id] = {
                    "entity_name": hit.entity.get("entity_name"),
                    "entity_type": hit.entity.get("entity_type"),
                    "neo4j_id": neo4j_id,
                    "score": 0.0,
                    "attribute": {
                        "name": hit.entity.get("attribute_name"),
                        "value": hit.entity.get("attribute_value")
                    }
                }
            else:
                fused_dict[neo4j_id]["score"] += score
                if "attribute" not in fused_dict[neo4j_id]:
                    fused_dict[neo4j_id]["attribute"] = {
                        "name": hit.entity.get("attribute_name"),
                        "value": hit.entity.get("attribute_value")
                    }
        
        for hit in relation_results:
            neo4j_id = hit.entity.get("neo4j_relation_id")
            score = hit.score * relation_weight
            relation_key = f"relation_{neo4j_id}"
            if relation_key not in fused_dict:
                fused_dict[relation_key] = {
                    "source_entity": hit.entity.get("source_entity_name"),
                    "target_entity": hit.entity.get("target_entity_name"),
                    "relation_type": hit.entity.get("relation_type"),
                    "neo4j_relation_id": neo4j_id,
                    "score": score
                }
        
        sorted_results = sorted(
            fused_dict.values(), 
            key=lambda x: x["score"], 
            reverse=True
        )
        
        filtered_results = [
            r for r in sorted_results if r["score"] >= 0.6
        ]
        
        return filtered_results

engine = HybridSearchEngine(
    uri="https://in01-xxxxxx.aliyun-cn-shanghai.vectordb.zilliz.com.cn:19530",
    token="db_admin:xxxxxx"
)

query_vector = np.random.rand(1024).tolist()
results = engine.hybrid_search(query_vector, top_k=10)

for result in results:
    print(f"实体: {result.get('entity_name', 'N/A')}, "
          f"类型: {result.get('entity_type', 'N/A')}, "
          f"综合得分: {result['score']:.4f}")
```

### 3.7 混合检索设计

#### 3.7.1 三集合检索策略

系统采用三集合并行检索策略，从不同维度匹配用户查询：

**检索集合**：

1. **medical_entity**：实体名称检索
   - 检索目标：实体名称与查询的语义相似度
   - 适用场景：实体识别、实体链接
   - 返回结果：实体名称、实体类型、Neo4j节点ID
2. **entity_attributes**：实体属性检索
   - 检索目标：实体属性内容与查询的语义相似度
   - 适用场景：基于症状、病因、预防措施等属性的检索
   - 返回结果：实体名称、属性名、属性值、Neo4j节点ID
3. **entity_relations**：实体关系检索
   - 检索目标：实体关系描述与查询的语义相似度
   - 适用场景：基于关系语义的检索（如"高血压会引起什么症状"）
   - 返回结果：源实体、目标实体、关系类型、Neo4j关系ID

#### 3.7.2 结果融合算法

**加权融合策略**：
采用加权融合算法综合三个集合的检索结果，权重分配如下：

| 检索集合               | 权重   | 说明                |
| ------------------ | ---- | ----------------- |
| medical_entity    | 0.40 | 实体名称匹配权重最高，优先级最高  |
| entity_attributes | 0.35 | 属性匹配权重次之，提供详细语义信息 |
| entity_relations  | 0.25 | 关系匹配权重较低，补充关联信息   |

**融合算法流程**：

1. **并行检索**：同时对三个集合进行Top-K检索（K=20）
2. **结果去重**：基于Neo4j节点ID/关系ID去除重复结果
3. **分数归一化**：将各集合的相似度分数归一化到[0,1]区间
4. **加权融合**：按权重计算综合得分
   ```
   综合得分 = 0.40 × 实体名称相似度 + 0.35 × 属性相似度 + 0.25 × 关系相似度
   ```
5. **结果排序**：按综合得分降序排列
6. **阈值过滤**：过滤综合得分低于0.6的结果

**融合优势**：

- **多维度匹配**：从实体名称、属性、关系三个维度全面匹配查询意图
- **语义增强**：属性和关系向量提供更丰富的语义信息
- **召回率提升**：三集合并行检索提高召回率，减少遗漏
- **精准度提升**：加权融合平衡不同维度的匹配结果，提高精准度

#### 3.7.3 检索性能优化

**性能优化策略**：

1. **并行检索**：使用多线程并行检索三个集合，减少总检索时间
2. **结果缓存**：对高频查询结果进行缓存，减少重复计算
3. **索引优化**：定期重建索引，优化查询性能
4. **批量查询**：支持批量查询，减少网络开销

**性能指标**：

- 并发查询QPS：>100
